译路畅通 · 使用说明
====================

一、怎么用
1. 双击「启动译路畅通.bat」
2. 会自动打开浏览器：http://127.0.0.1:8818
3. 主页右上角有「男声 / 女声」开关，点一下即可丝滑切换
   - 女声 = 冰糖（默认）
   - 男声 = 苏打
4. 数字读法：2 位连读（38 → 三十八），3 位及以上逐位读（5025 → 五零二五）
5. 关闭那个黑色命令行窗口 = 停止服务

二、登录（可选，不登录也能用全部功能）
- 首页「今日 X 单」旁边的「登录」按钮
- 注册：手机号 + 密码（至少 8 位）
- 登录后：
  * 送餐记录存到云端，换手机登录也能看到
  * 送餐地址、取餐点自动记下来
  * 第一次登录会把本机没登录时记的单合并到账号
- 退出登录后，记录退回「只存本机」，功能照常
- 账号页里可以「修改密码」；没开通短信服务时忘记密码看 README 的管理员重置

三、同地址自动补全
- 送餐：输入去过的小区 → 下面出候选；选中或输完点别处，
  楼栋 / 房号 / 楼层按上次自动填好
- 取餐：输入去过的「取餐点 / 商家」→ 选中后显示上次尾号 / 取餐码，
  点「沿用上次」才填取餐码（每单不同，避免送错）

四、电话里让顾客听到
1. 进「送餐 / 取餐」对话页，右上角点「电话」
2. 填顾客手机号 → 拨号 → 接通后开「免提」
3. 点句子播放；建议先点「提前缓存本页语音」
4. 网页不能直接插进运营商通话，只能免提外放；
   服务器外呼/双向中转方案见 docs/电话播报方案.md

五、文件夹内容
- index.html              前端页面（里面不含 API Key）
- server.py               后端（TTS + 账号 + 地址簿 + 送餐记录）
- manifest.json / sw.js / icon-*.png   PWA 安装与离线
- data/                   第一次运行后生成，存账号和记录，别删、别外发
- tests/                  后端自测
- deploy/ + docs/         Ubuntu 部署和电话方案
- 启动译路畅通.bat          Windows 一键启动
- 使用说明.txt             本文件

六、注意
- 需要联网（语音在 MiMo 云端合成；不配 Key 会用浏览器语音）
- 需要电脑装有 Python 3.9 或更高
- API Key 写在「启动译路畅通.bat」里，别把这个文件夹发给别人
- 部署到 Ubuntu 服务器：请看 README.md 和 docs/Ubuntu部署.md

七、新功能（2026-11）
- 首页左上角城市/天气：服务端接高德 Web服务 API，按网络位置自动定位；
  点城市名可以请求手机精确定位。
- 首页背景：按城市抓取不同风景图（Bing 图片），失败保留内置图。
- 填地址/取餐页：最上面是「截图识别」主按钮，从相册选订单截图即可自动填；
  下面「粘贴识别（兜底）」保留。
- 截图识别需要服务器装 tesseract-ocr / tesseract-ocr-chi-sim；识别结果请再核对一遍。

八、定位说明（2026-11）
- 首次进入首页会直接弹出浏览器的「定位权限」请求：
  - 允许：按手机 GPS/网络精确取城市；
  - 拒绝或超时：自动退回 IP 城市（可能不是实际城市，仅兜底）。
- 首页初始不再写死「济南」，先显示「定位中…」；定位失败显示「定位失败 · 点此重试」。
- 城市图片的「图源 Bing」已移到图片右下角。

- 定位结果会保存到浏览器 localStorage（键 `ylct_geo_cache_v1`）：
  第一次允许定位后，刷新/重开网页直接使用缓存城市，不再重复弹定位权限；
  点左上角城市名才会重新定位。清除浏览器站点数据后会重新询问。

九、默认值（2026-11）
- 送餐页、取餐页、对话页不再预填「阳光小区 / 3号楼 / 602 / 13800135025 / 38 / 肯德基」等演示信息；
- 输入框只保留泛化提示，如「小区名称」「楼栋」「房号」「商家名称」「手机尾号」「取餐码」；
- 楼层默认不选中；不再自动编房号；
- 旧版本留下的这套演示地址会在首次打开时自动清理；你自己真实填过的其他地址会保留。

十、截图识别改进（2026-11-08）
- 手机截图默认保留原图（≤3.5MB、≤3000px 不压缩），大图最多 2400px/JPEG 90%，不再把 1320×2868 压成 736×1600；
- OCR 文本支持“地址”后面没有冒号的截图，按行提取地址；
- “青岛城市学院”不会再被当成“青岛市”剥成“学院”；
- 支持 A1宿舍楼/5栋 等楼栋写法，以及 Lzc 这类英文联系人。
- 门牌号（如“西门”）目前没有对应输入框，不会自动填；需要的话可再加。

十一、远程 OCR（2026-11-08）
- 云服务器优先调用性能更好的机器上的 RapidOCR；远程超时/离线时自动回退服务器 Tesseract。
- 识别服务在 `ocr-service/`：Mac 双击 `run.command`，首次自动安装 RapidOCR。
- 临时可用 SSH 反向隧道：`ssh -N -R 19000:127.0.0.1:9000 root@117.72.107.56`，
  云服务器 `.env` 配 `OCR_REMOTE_URL=http://127.0.0.1:19000/ocr`。
- 长期建议 Cloudflare Tunnel，详见 `ocr-service/README.md`。
- 截图上传压到长边 1800、JPEG 90%，约 150KB；实测远程 OCR 约 1.1 秒，接口端到端约 1.3–1.5 秒。

十二、腾讯云 OCR（2026-11-08）
- 资源包列表里没有普通 General OCR，只有“通用文字识别Agent-1千页”，因此改用 RecognizeAgent（QueryType=0）。
- 云优先，服务器本地 Tesseract 兜底；Mac 隧道已撤掉。
- 前端截图压到 1800px/约150KB，实测云 OCR 约 1.3 秒；原图约 3.9 秒。
- 免费包 1000 页，注意控制台余量；用完会回退本地 OCR。

十三、取餐信息同步到送餐（2026-11-08）
- 取餐页截图/粘贴订单后，会同时解析送餐地址和手机号：
  - 地址、楼栋、房号、楼层写入送餐草稿；
  - 取餐码、商家、手机号写入取餐；
  - 切到“送餐”页时自动出现，不用再填。
- 只手动填取餐码/商家/手机号时，手机号会作为本单联系电话保留；没有地址就不会凭空生成地址。
- 若截图里没有取餐码，不会再把门牌号/距离/手机号误当成取餐码。

十四、首页每日 5 张城市壁纸（2026-11-08）
- 后端按“城市 + 北京时间日期”生成 5 张候选，缓存 24 小时；
- 前端首页固定 5 张 slide，每 5 秒轮换，跨天刷新会换一组；
- 先预加载第一张再切换，避免白屏；取不到图时保留原内置图。

十五、双地址订单截图（2026-11-08）
- 真实订单截图常为“上面取货地址、下面送货地址”；
- 现在第一段地址写入取餐页新增的“取货地址（选填）”，第二段写入送餐地址；
- 第一个商家名（如“美悦美妆集合店”）会填入取餐点；
- “A栋15楼”会拆成楼栋 A栋、楼层 15；
- 一张截图有多单时，只取最上面一单，并提示“多单只取第一单”；
- 想识别第二单请单独截那一单，避免两单地址混在一起。

十六、手机号默认值（2026-11-08）
- 取餐页手机号不再从 localStorage 自动恢复，刷新后默认空；
- 只有当前订单截图 OCR、手动输入或主动选历史商家时才填；
- 旧版保存在 cs_last_v1 的号码会被忽略；如果当前页仍显示，强刷一次。

十七、订单记录范围（2026-11-08）
- 记录页展示近 30 天每日记录；
- 顶部新增近 7 天、本月、今年三个合计；
- 登录后数据拉取一年，年度合计能覆盖当前年份。

十八、文案精简（2026-11-08）
- 大标题下不再放解释性副标题；
- 首页步骤、模式卡、大字牌、记录页说明均已精简；
- 操作说明集中在首次引导里。
