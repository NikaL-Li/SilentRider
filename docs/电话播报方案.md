# 电话播报：怎么让顾客在电话里听到网页的语音

> 结论先说：**普通网页无法把声音“直接插进”运营商通话的上行音频。**
> 浏览器没有权限、也没有 API 去接管手机通话的麦克风通道。能可靠落地的只有下面几条路，
> 项目里已经实现了成本最低、当天就能用的 **免提外放**，并为 **服务器语音外呼** 留好了接口。

---

## 1. 为什么不能直接“插进”电话

手机通话的音频链路在操作系统/基带层：

```
麦克风 → 系统通话栈 → 运营商网络 → 对方手机听筒
```

网页（Safari / Chrome / 微信内置浏览器）只能：

- 播放声音到 **本机扬声器 / 听筒 / 蓝牙**；
- 用 `getUserMedia` 拿麦克风；
- 不能把一段音频写进“当前这通电话”的上行流。

所以网页播放的 TTS 只有两种命运：

1. 从手机扬声器放出来，被本机麦克风（免提时）拾取，进入通话 → **声学外放**；
2. 走另一条网络通话/外呼通道（WebRTC、SIP、云通信）→ 需要服务器和号码资源。

iOS 的 `navigator.audioSession.type = 'playback'` 只能影响“本机从哪个扬声器出”，
不能改变“对方能不能听到”，更绕不开运营商。

---

## 2. 五条路线对比

| 路线 | 对方能听到 | 对方能回话 | 成本 | 上线难度 | 适用 |
|---|---|---|---|---|---|
| A. 免提外放（已实现） | ✅ 音质一般 | ✅ 正常通话 | 0 | 今天就能用 | 现在立刻用 |
| B. 云端语音外呼（已留接口） | ✅ 音质好 | ❌ 单向 | 按分钟计费 + 号码资质 | 中 | 通知类一句话 |
| C. 双向语音中转（方案） | ✅ | ✅（ASR 转文字） | 较高 | 高 | 完整替代打电话 |
| D. 系统级 AI 通话/畅听王卡 | ✅ | ✅ | 运营商套餐 | 无需开发 | 过渡期推荐 |
| E. 语音链接/二维码 | ✅（点开听） | ❌ | 0 | 低 | 不在通话时 |

### A. 免提外放（本项目已实现）

流程：

1. 骑手在 App 里点「电话」，输入顾客号码，点「拨号」；
2. 接通后打开手机 **免提**，把手机放在嘴边/餐箱上；
3. 点要说的句子，App 用最大音量播放 TTS；
4. 顾客手机听筒里听到的是“免提扬声器 → 骑手手机麦克风 → 运营商”的声音。

代码位置（`index.html`）：

- `openCall()`：打开通话面板，列出当前场景的句子；
- `playLoud()`：Web Audio 增益 1.8 + 压缩器，尽量避免破音，比直接 `<audio>` 更响；
- `prefetchCallAudio()`：拨号前把本页句子缓存成 Blob，**通话中数据断掉也能播**；
- `navigator.audioSession.type = 'playback'`：iOS 上尽量走媒体播放通道。

注意：

- **必须开免提**。不开免提时声音从听筒出，对方基本听不到。
- **播放时页面要留在前台**。切到电话 App 后，浏览器可能被系统挂起；
  实际用法是：先缓存 → 点「拨号」→ 接通 → 切回浏览器 → 点句子。
- iOS 在通话期间可能打断/降低网页音频；Android 各厂商策略也不同，必须真机验证。
- 关掉蓝牙耳机；蓝牙会把声音抢走。
- 音量键要手动开到最大，网页不能改系统音量。
- 环境嘈杂、风大时对方可能听不清；可先用「大字牌」辅助。
- 部分运营商/VoLTE 在通话中会限制数据；所以先点「提前缓存本页语音」。
- 回音：对方如果也开免提，可能啸叫，建议对方用听筒。

> 也正因为“切前台 + 系统打断 + 免提音质”这三座大山，产品化时应优先做
> 服务器外呼或双向语音中转，而不是只依赖网页免提。

### B. 云端语音外呼（接口已留）

```
骑手点“服务器外呼”
      ↓
本项目 POST /api/call {phone, text}
      ↓
YLCT_CALL_WEBHOOK 指向的语音网关
      ↓
阿里云语音通知 / 腾讯云语音消息 / FreeSWITCH / Asterisk / Twilio
      ↓
顾客手机响铃，接听后听到 TTS
```

优点：音质好、不依赖骑手手机扬声器、顾客不用先和骑手通话。
缺点：**单向**，顾客说话骑手听不到；需要企业实名、号码资质、模板报备；按分钟计费。

启用方式（详见第 4 节）：

```bash
YLCT_CALL_WEBHOOK=https://your-gateway.example.com/call
YLCT_CALL_TOKEN=change-me
```

没配置时，页面只显示免提播报，不会误导用户。

### C. 双向语音中转（真正的“电话翻译”）

这是“畅听王卡 / AI 通话”类产品的做法：

```
顾客拨打虚拟号码（或点 WebRTC 链接）
        ↓
SIP / WebRTC 网关（FreeSWITCH、Asterisk、声网、腾讯云 TRTC）
        ↓
ASR：顾客说话 → 文字 → 骑手屏幕
        ↓
骑手点句子 / 打字 → TTS → 混回通话音频 → 顾客听到
```

需要：SIP/WebRTC 服务、号码资源、ASR、TTS、回声消除、打断（barge-in）、延迟控制（建议端到端 < 1.5 秒）。
合规要求也最高（增值电信业务、呼叫中心资质、号码实名、防骚扰）。
适合作为下一步产品化方向，不建议在比赛 Demo 阶段自建。

### D. 系统级 AI 通话（零开发，推荐写进使用引导）

国内已有面向听障用户的系统级能力：

- 中国联通「畅听王卡」AI 通话；
- 小米 / 华为 / 荣耀的「AI 通话」；
- 讯飞听见等转写服务。

它们能在运营商通话链路上做“文字转语音”，效果比免提外放稳定。
可以在 App 里加一句提示，引导用户优先开启系统 AI 通话，网页作为补充。

### E. 语音链接 / 二维码（兜底）

把一句话生成一个短语音页面（或直接发语音文件），顾客点开就能听。
适合“顾客不方便接电话”“需要反复听地址”的场景，不属于实时通话。

## 3. 本项目里的“电话”按钮怎么用

1. 进入「送餐」或「取餐」对话页；
2. 右上角点 **电话**；
3. 填顾客手机号 → **拨号**；
4. 接通后开免提；
5. 点句子播放；也可以先点「提前缓存本页语音」。

页面会明确提示“网页不能直接插进运营商通话”，避免用户误解。

## 4. 服务器外呼网关契约

### 请求

`POST /api/call`（本项目，登录可选，有限流）

```json
{ "phone": "13800135025", "text": "您好，我是送外卖的，麻烦开一下门" }
```

成功后返回：

```json
{ "ok": true, "detail": "gateway response" }
```

### 本项目回调网关

配置 `YLCT_CALL_WEBHOOK` 后，服务端会向它发：

```http
POST /call
Authorization: Bearer <YLCT_CALL_TOKEN>
Content-Type: application/json

{ "phone": "13800135025", "text": "您好，我是送外卖的", "source": "ylct" }
```

网关只要在 15 秒内返回 2xx 即可；异步排队也可以。

### 网关可以怎么实现

- **阿里云语音通知 / 腾讯云语音消息**：买号码 + 报备模板，调用官方 API 发起外呼并播放 TTS。
  注意：模板通常要求固定文案/变量，不能任意长文本；需要企业资质。
- **FreeSWITCH / Asterisk**：自建 SIP 网关，`originate` 呼叫顾客，接通后 `playback` 一段 TTS 音频；
  需要公网 SIP 端口、号码中继、防炸号策略。
- **Twilio / Plivo**（海外）：`<Say>` TwiML 最省事，但国内号码可达性和合规性要单独评估。
- **自建 HTTP → SIP 小服务**：收到上面的 JSON，调用 `fs_cli -x "originate ..."` 即可，几十行代码。

测试：

```bash
curl -X POST http://127.0.0.1:8818/api/call \
  -H 'Content-Type: application/json' \
  -d '{"phone":"13800135025","text":"您好，我是送外卖的"}'
```

未配置时返回 `503 call_not_configured`，前端会提示改用免提。

### 安全建议

- 网关必须校验 `YLCT_CALL_TOKEN`，不要裸奔；
- 本项目已按 IP / 手机号限流（默认 10 次/小时/IP、3 次/小时/号码），生产环境建议再加登录要求：
  `YLCT_CALL_REQUIRE_LOGIN=1`；
- 不要在日志里记录完整手机号；
- 呼叫前确认用户同意，遵守《个人信息保护法》和防骚扰要求；
- 设置白名单/黑名单和每日预算上限。

## 5. 上线节奏建议

1. **现在**：免提外放 + 提前缓存语音，覆盖大多数“门禁/放门口/找不到”场景；
2. **下一步**：接通阿里云/腾讯云语音通知，做“单向通知”（例如“餐到门口了”）；
3. **产品化**：WebRTC/SIP + ASR 做双向中转，才真正接近“打电话”的体验；
4. 同时在 App 内引导用户开启手机自带 AI 通话，作为最稳的兜底。
